# Создание `build.exe`

Репозиторий **не содержит бинарных файлов**. Основной официальный исходный
сценарий сборки — `build.py`; `build.exe` является только необязательным
Windows-загрузчиком для привычной по проектам SS13 точки входа.

## Сборка загрузчика

1. Установите MinGW-w64 с `x86_64-w64-mingw32-gcc` версии **13.2.0** и добавьте
   каталог компилятора в `PATH`.
2. Откройте `cmd.exe` в корне TerraNore.
3. Выполните:

   ```bat
   BUILD\rebuild-build-exe.cmd
   ```

4. Скрипт создаст `BUILD\build.exe`. Теперь тестовую сборку можно запустить:

   ```bat
   BUILD\build.exe
   ```

Скрипт получает точную версию командой
`x86_64-w64-mingw32-gcc -dumpfullversion` и **прерывает сборку**, если результат
не равен `13.2.0`. Таким образом, EXE, полученный другим компилятором, нельзя
случайно принять за воспроизводимый артефакт.

Загрузчик получает аргументы через Unicode Windows API и передаёт их
`build.py` без изменений, включая пустые значения, кавычки, обратные слеши и
пути с пробелами. Для быстрой проверки передачи параметров в `cmd.exe`
используйте, например:

```bat
BUILD\build.exe --build-only
BUILD\build.exe --no-browser --port 8765
BUILD\build.exe --output "путь с пробелами"
```

Последние две команды после сборки запускают сервер, как и соответствующий
прямой вызов `py -3 BUILD\build.py`; остановить его можно сочетанием `Ctrl+C`.

## Группа процессов TerraNore в Windows

`build.exe` создаёт Windows Job Object `TerraNore.Build` с флагом
`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. `build.py` запускается приостановленным,
добавляется в job-объект и только затем продолжает работу. Поэтому сервер и
созданные им процессы `ProcessPoolExecutor` наследуют членство в том же
job-объекте; закрытие загрузчика завершает всё дерево процессов.

В обычном **Диспетчере задач** откройте вкладку «Подробности», включите столбец
«ИД процесса» и найдите `python.exe`/`pythonw.exe` по PID из блока `WORKERS` в
интерфейсе TerraNore. В блоке показаны PID сервера, PID реально запущенных
workers, их фактическое число и ID группы. Workers создаются лениво, поэтому до
первого параллельного расчёта список может быть пуст.

В **Process Explorer** найдите PID сервера (`Find` → `Find Process…`) и включите
древовидный режим (`View` → `Show Process Tree`): workers видны как дочерние
процессы сервера, а `build.py` — как родитель сервера. В свойствах процесса на
вкладке `Job` отображается принадлежность к `TerraNore.Build`; одинаковая
запись у сервера и workers подтверждает наследование job-объекта. PID и ID
группы предназначены только для диагностики и никогда не заменяют отдельный
токен управления задачей.

Используемая команда компилятора полностью записана в
`rebuild-build-exe.cmd`. Целевая архитектура зафиксирована как **Windows
x86-64** одновременно префиксом компилятора `x86_64-w64-mingw32-gcc` и флагом
`-m64`. Полный набор флагов имеет вид:

```text
-m64 -Os -s -municode -mconsole build_launcher.c -Wl,--no-insert-timestamp -lshell32 -o build.exe
```

Linker flag `--no-insert-timestamp` исключает изменяемую временную метку из
PE-файла; `-lshell32` фиксирует системную библиотеку загрузчика. Исходник
загрузчика находится в `build_launcher.c`, а вся содержательная логика — в
читаемом `build.py`.

Для проверки воспроизводимости соберите файл из одного и того же checkout в
двух чистых каталогах и в каждом выполните из корня репозитория:

```powershell
(Get-FileHash -Algorithm SHA256 .\BUILD\build.exe).Hash
```

Обе 64-символьные строки SHA-256 должны полностью совпасть. Хеш относится к
байтам PE-файла, поэтому такое сравнение одновременно обнаруживает различия в
заголовках и секциях. Для публикуемого артефакта следует сохранить эту строку
рядом с указанием commit и повторно сверить её после скачивания той же командой.

## Без EXE

Создавать загрузчик не обязательно. На Windows официальный сценарий можно
запустить непосредственно:

```bat
py -3 BUILD\build.py
```

На Linux и macOS используйте `./BUILD/build`. Python 3.10 или новее является
единственной зависимостью самой сборки TerraNore.
