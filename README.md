# TerraNore Test

Локальный тестовый стенд детерминированной экономической симуляции. Ядро не
зависит от HTTP, WebSocket или DOM и может использоваться отдельно для быстрых
прогонов.

## Тестовая сборка

Это **тестовая**, а не производственная сборка. TerraNore использует Python и
обычный локальный HTML-интерфейс, а не BYOND/Dream Maker; от принятой в проектах
SS13 схемы здесь используется только знакомая точка входа `BUILD\build.exe`.
Внешний инструментарий SS13 не требуется.

Бинарные файлы в репозитории не хранятся. Чтобы получить привычный Windows
загрузчик, один раз выполните из корня репозитория:

```bat
BUILD\rebuild-build-exe.cmd
BUILD\build.exe
```

Подробная пошаговая инструкция находится в `BUILD/README.md`. Для создания EXE
требуется точная версия `x86_64-w64-mingw32-gcc 13.2.0`: скрипт проверяет её
через `-dumpfullversion` и при несовпадении завершает сборку. Целевая архитектура
загрузчика — Windows x86-64. Команда линковки и проверка SHA-256 полученного
PE-файла документированы в `BUILD/README.md`. EXE проверяет Python 3.10+,
собирает (проверяет bytecode) ядро, копирует HTML, создаёт автономный тестовый
дистрибутив и запускает локальный сервер. Исходный алгоритм сборки открыт в
`BUILD/build.py`. Сам EXE — только нативный загрузчик, собираемый из
`BUILD/build_launcher.c`; это не бинарник из внешней поставки SS13.

Альтернативная текстовая команда, в том числе для Linux/macOS:

```bash
./BUILD/build
```

На Windows тот же скрипт можно вызвать без EXE: `py -3 BUILD\build.py`. Готовое
приложение находится в `BUILD/out/TerraNore-Test/`. Сборщик сначала работает во
временном каталоге и атомарно заменяет только этот выходной каталог: исходники и
пользовательские сохранения он не изменяет. Только собрать дистрибутив можно так:

```bash
python3 BUILD/build.py --build-only
```

Сервер выбирает свободный локальный порт и пытается открыть HTML-интерфейс в
браузере по адресу `http://127.0.0.1:<port>`. После сборки интерфейс также можно
запустить вручную командой `BUILD\out\TerraNore-Test\run.cmd` (Windows) или
`BUILD/out/TerraNore-Test/run.sh` (Linux/macOS). Чтобы закрепить порт и не
открывать браузер, используйте:

```bash
python3 BUILD/build.py --no-browser --port 8080
```

Журнал сборки записывается в `BUILD/logs/build.log`, журнал запущенного сервера —
в `BUILD/out/TerraNore-Test/logs/server.log`. Каталог сохранений готового
приложения — `BUILD/out/TerraNore-Test/saves/`; обычные операции API принимают
только относительное имя внутри настроенного каталога сохранений.

## Проверки и быстрый прогон ядра

```bash
python -m unittest discover -s tests -v
python -m src.simulation --years 100 --seed 42 --workers auto
```

Вторая команда запускает тестовый сценарий ровно на 100 лет. Число потоков
переключается параметром `--workers auto`, `--workers 1` или, например,
`--workers 4`; тот же выбор доступен в поле «РАБОЧИЕ ПОТОКИ» HTML-интерфейса.

`--workers` принимает `auto` (число доступных логических процессоров), `1`
(эталонный последовательный режим) или положительное целое число для
профилирования. Для обхода Python GIL вычисления выполняются отдельными
процессами и действительно могут занимать разные ядра CPU. Тик выполняется
барьерными фазами: рабочие процессы читают только
неизменяемый снимок и возвращают дельты, которые применяются в стабильном
порядке. Очередь задач и журналы истории/событий ограничены, поэтому длительный
прогон не накапливает неограниченный объём ожидающей работы.

Тестовый HTTP API размещён под `/api/test/v1`, WebSocket — по адресу
`/api/test/v1/ws`, формат сохранения — `test-save-v1`. WebSocket остаётся
открытым до отключения клиента и после каждого атомарного тика отправляет
компактное уведомление: `revision`, `currentDate`, `activeTask`, `summary` и
`changedObjectIds`. Полное состояние интерфейс забирает через `GET /state`;
частые уведомления одного прогона объединяются перед запросом.

Сервер по умолчанию и принудительно слушает только loopback-интерфейс. API
публикует номер `revision` вместе с отделёнными от модели DTO. Основные ресурсы:

* `POST /worlds`, `GET /state`, `POST /simulation/step`;
* `POST /simulation/run` и `GET /tasks/{id}`; управление выполняется через
  `POST /simulation/pause`, `/simulation/resume` и `/simulation/cancel`;
* `GET /nodes/{id}/children`, `GET /objects/{id}` и
  `PUT /objects/{id}/lod` (поле `level` принимает только `auto`, `lod-0`,
  `lod-1` или `lod-2`);
* `GET /timeseries`, `/compare`, `/events`, `/events/{id}/causes` и
  `/anomalies` (границы периода задаются параметрами `from` и `to`);
* `POST /snapshots`, `POST /snapshots/{id}/open`, `POST /save` и `POST /load`.

Длительный прогон возвращает HTTP 202, идентификатор задачи, прогресс и токен
отмены. Пауза применяется между атомарными тиками: опубликованное состояние
мира при этом всегда согласовано. Открытый снимок неизменяем; попытки шага или
смены LOD возвращают HTTP 409.

### Имперский календарь

Начальная дата мира по умолчанию — `01.1\1.1.4300`. Год состоит из четырёх
кварталов, квартал — из трёх третей, треть — из трёх декад по десять дней.
Запись `день.декада\треть.квартал.год` используется в DTO, WebSocket и файлах
сохранений. Один тик модели соответствует одной трети квартала (30 дням).
`POST /simulation/run` может принимать `targetDate`; сервер переводит её в
номер тика относительно эпохи конкретного мира и отклоняет прошедшие либо
выходящие за поддерживаемый диапазон даты.

## Структура

* `src/simulation/model/` — состояния мира и экономики;
* `src/simulation/systems/` — последовательные фазы тика;
* `src/simulation/lod/` — правила детализации;
* `src/simulation/workers/` — детерминированный планировщик;
* `src/server/` — локальный API;
* `src/ui/` — браузерный интерфейс;
* `src/persistence/` — раздельные оперативное состояние, copy-on-write снимки,
  многоуровневые временные ряды и постоянный журнал событий. Снимок открывается
  только для чтения; продолжение от него создаётся запросом
  `POST /snapshots/{id}/branch` с новым `branchId`;
* `tests/` и `BUILD/` — проверки и команды запуска.

### Безопасность сохранений

`POST /save` и `POST /load` принимают поле `name` (либо `id`) с относительным
идентификатором внутри настроенного каталога `saves/`; абсолютные пути и
компоненты `..` запрещены. Запись выполняется через временный файл с атомарной
заменой. Импорт произвольного внешнего пути отделён в developer-операцию
`POST /developer/import` и отключён по умолчанию. Для локальной разработки её
можно явно включить флагом `--enable-developer-import`; операция принимает
внешний путь в поле `path`. Каталог можно настроить флагом `--saves-dir`.
